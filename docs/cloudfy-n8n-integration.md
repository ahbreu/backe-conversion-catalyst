# Cloudfy/n8n lead capture integration

## Current environment

- Company: `BACKE.co`
- Website stack: React/Vite frontend with an Express backend in `backend/server.js`
- Default environment: `sandbox`
- Cloudfy/n8n base URL: `https://groundedlungfish-n8n.cloudfy.live`
- Website lead endpoint: `POST /api/leads`

The website must call the Express backend first. The backend validates and normalizes the lead, then forwards it to n8n.

## How forms submit leads

`src/components/ContactForm.tsx` submits to `${VITE_API_URL}/api/leads`. The backend route:

1. Rejects honeypot submissions.
2. Normalizes name, phone, email, page data, UTM, seller and metadata.
3. Validates required fields: name and phone. Email is optional but validated when present.
4. Applies basic rate limiting by IP.
5. Skips duplicate submissions inside `LEAD_IDEMPOTENCY_WINDOW_MS` and adds `metadata.idempotencyKey`.
6. Saves the normalized lead locally in SQLite before calling n8n when `LOCAL_LEAD_DB_ENABLED=true`.
7. Sends the payload to `N8N_LEAD_CAPTURE_WEBHOOK_TEST_URL` while `APP_ENV=sandbox`.
8. Retries only retryable n8n failures, such as timeout, `429`, and `5xx`.
9. Updates the local SQLite status to `n8n_forwarded` or `n8n_failed`.
10. Returns only a safe website response:

```json
{
  "ok": true,
  "message": "Lead sent successfully"
}
```

Current lead form connected:

- `#formulario` in `src/components/ContactForm.tsx`

Current lead CTAs connected:

- Hero CTA: selects `Diagnóstico estratégico` and scrolls to the form.
- Service CTAs: select the clicked service and scroll to the form.
- Maintenance CTA: uses WhatsApp when `VITE_PUBLIC_WHATSAPP_PHONE` is set; otherwise falls back to email.

## Backend hardening

The Express backend includes production-oriented defaults without adding third-party packages:

- CORS allowlist from `FRONTEND_URL`.
- Request IDs via `X-Request-Id`.
- Structured JSON logs for Cloudfy health, validation failures, rate limits, duplicate skips, and n8n forwarding.
- Body size limit of `64kb`.
- Local SQLite persistence before n8n forwarding, so leads are not lost if automation is unavailable. On Windows, the default database path is `%LOCALAPPDATA%\BACKE.co\lead-db\leads.sqlite`.
- Rate limit for `POST /api/leads` with `RATE_LIMIT_WINDOW_MS` and `RATE_LIMIT_MAX`.
- In-memory duplicate prevention with `LEAD_IDEMPOTENCY_WINDOW_MS`.
- n8n timeout and retry controls through `N8N_REQUEST_TIMEOUT_MS`, `N8N_RETRY_ATTEMPTS`, and `N8N_RETRY_BASE_DELAY_MS`.
- `TRUST_PROXY=false` by default. Set it to `true` only when the backend runs behind a trusted reverse proxy, so client IP handling cannot be spoofed through `X-Forwarded-For`.

For multi-instance production deployments, move rate limit and idempotency state to Redis or a database.

## How to test locally

Install frontend dependencies from the repo root and backend dependencies from `backend/` if needed.

```sh
npm install
cd backend
npm install
```

Create `.env.local` from `.env.example`, then start the backend:

```sh
node backend/server.js
```

Start the Vite site:

```sh
npm run dev
```

Open the local site, fill the form with fake BACKE.co data, and submit. The browser should call `POST http://localhost:3001/api/leads`, and the backend should forward to the sandbox n8n webhook.

Run the Cloudfy/n8n healthcheck:

```sh
npm run test:cloudfy
```

Run a direct fake lead-capture webhook test:

```sh
npm run test:lead
```

The direct lead test uses a fake phone placeholder and does not include customer data.

Run local backend helper checks:

```sh
npm run test:backend
```

## What n8n must do

The lead-capture workflow should:

1. Receive the payload from the website backend.
2. Validate `company`, `environment`, `lead.name`, and `lead.phone`.
3. Create `public.leads_site` if the table does not exist.
4. Store the lead in PostgreSQL before sending WhatsApp.
5. Preserve the saved `lead_id` for WhatsApp messages, status updates, and the response.
6. Send a WhatsApp notification to the client through Evolution API.
7. Send a WhatsApp notification to the seller through Evolution API.
8. Update the lead status to `whatsapp_enviado` after both sends succeed.
9. Update the lead status to `erro_envio` if one of the sends fails.
10. Respond to the website with:

```json
{
  "ok": true,
  "company": "BACKE.co",
  "environment": "sandbox",
  "leadReceived": true,
  "leadId": "1",
  "message": "Lead received"
}
```

Workflow file: [`workflows/backe-lead-whatsapp.json`](../workflows/backe-lead-whatsapp.json).

Detailed n8n setup guide: [`docs/n8n-backe-lead-whatsapp.md`](./n8n-backe-lead-whatsapp.md).

## WhatsApp notification

WhatsApp messages must be sent by n8n through Evolution API, never by the frontend. Suggested seller notification:

```text
Novo lead BACKE.co
Nome: {{ lead.name }}
WhatsApp: {{ lead.phone }}
Email: {{ lead.email || "não informado" }}
Empresa: {{ lead.companyName || "não informado" }}
Interesse: {{ lead.serviceInterest || "não informado" }}
Origem: {{ source }} - {{ pageUrl }}
```

Still needed:

- Evolution API base URL and credentials inside n8n credentials.
- WhatsApp instance/channel name.
- Seller destination phone in `DEFAULT_SELLER_PHONE` or n8n credentials/config.

## Database schema

The current workflow uses `public.leads_site`:

```sql
CREATE TABLE IF NOT EXISTS public.leads_site (
  id BIGSERIAL PRIMARY KEY,
  nome TEXT NOT NULL,
  telefone TEXT NOT NULL,
  email TEXT,
  servico TEXT DEFAULT 'outro',
  mensagem TEXT,
  origem JSONB DEFAULT '{}'::jsonb,
  consentimento JSONB DEFAULT '{}'::jsonb,
  metadata JSONB DEFAULT '{}'::jsonb,
  raw_payload JSONB DEFAULT '{}'::jsonb,
  status TEXT DEFAULT 'novo',
  whatsapp_cliente_enviado BOOLEAN DEFAULT false,
  whatsapp_vendedor_enviado BOOLEAN DEFAULT false,
  erro_envio TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

During development, the workflow creates this table automatically. Later, move this SQL to a migration or manual setup step and keep the workflow focused on lead insertion and status updates.

## Remaining production setup

- Import and activate [`workflows/backe-lead-whatsapp.json`](../workflows/backe-lead-whatsapp.json) in n8n.
- Create the n8n credential `Postgres Cloudfy` using PostgreSQL data from the Cloudfy panel.
- Move to the `/webhook/sandbox/backe/lead-capture` URL when ready and set `APP_ENV=production`.
- Deploy the Cloudflare Worker in [`worker/`](../worker) following [`production-cloudflare-worker.md`](./production-cloudflare-worker.md), then set the frontend `VITE_API_URL` to that Worker URL. The Express backend remains useful for local development.
- Configure the GitHub repository variable `VITE_API_URL` before publishing the GitHub Pages frontend. If it is missing, the production frontend will not fall back to `localhost`.
- Configure Evolution API URL, instance, API key, seller phone, database credentials, and Chatwoot credentials inside n8n.
